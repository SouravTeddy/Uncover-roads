Recommendation trigger conditions documented in code
Time window between stops falls in meal window → show food/café recs
Persona = walker OR pace = relaxed → only show recs within walking distance (~500m)
Persona = epicurean → prefer restaurant recs over café
Persona = explorer + outdoor stop → show viewpoint/park recs
Budget = budget → filter out expensive recs
Stop gap < 30 min → suppress recs (not enough time)
Max 2 rec branches visible at once (map readability)
Visual rules map rendering
Main route: solid polyline, 3.5px, primary color (#e07854), Google Directions style
Rec branch: dashed line, 1.8px, category color (amber=food, sage=café, sky=view)
Branch originates from midpoint of the leg, not from a stop
Tap rec marker → place card slides up with "Detour" badge instead of stop number
Rec markers are smaller (11px) than stop markers (14–18px)
Code architecture: A RECOMMENDATION_RULES constant in route/rec-rules.ts declares every condition explicitly — time windows, persona mappings, distance thresholds, max branches. The map layer reads these to decide which branches to render. Easy to add/edit rules without touching map rendering logic.
